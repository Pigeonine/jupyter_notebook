1. RestController 작성하기
@RestController -> @Controller + @ResponseBody?

client요청은 get/post 방식으로 나뉨. 
get방식(Get it): 페이지 연결이 주 목적, (데이터 전달이 주 목적이 아님), 모든 요청의 기본 (약 90%이상 차지) (데이터 전달이 가능하긴 하나, 많은 양을 보내지 않음) (데이터가 객체(Req)에 담기지 않는다)

Request: request.line, Header, Body로 구성.
request.line에 요청 부분(member)과 방식(get/post)적힘.
Header: browser 정보 같은 핵심 정보 들어감.
Body에는 map으로 정보 들어감 (id = sds, pw=1234, name=~), get 방식의 경우 body에 내용이 담기지 않는다.

get의 경우 주소에 query문이 담긴다?: http://203.234.12.225:9000/members?id=sds&name=James -> 보안 취약, 길이 제약, (객체에 담기지 않음/정보 전달이 목적이 아님)

post(Post office의 줄임말): 서버로 ~데이터 보낼테니, 서버는 해당 데이터를 서비스로 처리한 결과를 다시 나한테 보내라. 
데이터 전달이 주 목적.

Request 객체
request.line: 요청 url + post(members post) (요청 url의 이름은 복수형으로?(convention))
body: 원하는 정보 담김.

url: http://203.234.12.225:9000/members
